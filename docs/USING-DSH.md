# 怎么把 DSH 用好

2026-11-07 整理，DSH 0.2.2-rc.1。来源：DSH 源码里各功能包的说明、社区手册 [deepseek-harness-handbook](https://github.com/sandbaseai/deepseek-harness-handbook)、[DSH 实用指南](https://zicode.com/blog/dsh-practical-guide/)、高星插件的说明。下面说的东西装了 dsh-llm-ferry 都照常能用，模型调用一律经 Ferry 出去。

## 一句话

DSH 是 agent 的"身体"，模型是"脑子"。用得好不好，主要看五件事：选对预设、把规则写下来、把重复的做法写成技能、插件少而精、复杂活拆给子 agent。出了问题先看会话记录，别猜。

## 选对预设（Preset）

新建会话时选。差别很大：

| 预设 | 有什么 | 什么时候用 |
|---|---|---|
| Standard | 完整的编程 agent：改文件、命令行、检索、技能、计划、目标、子 agent、工作流 | 日常，九成任务用它 |
| PTC | 在 Standard 上把工具变成可编程接口，模型写一段脚本一次跑完多步 | 同样的批量活反复做（改几十个文件、批量处理文稿）：二十次来回变一次，省钱 |
| Minimal | 只有命令行和替换式编辑 | 排查"它刚才到底干了什么" |
| Creator | Standard 加插件开发工具 | 自己写插件、做预设 |

## 把规则写下来：AGENTS.md

每次都要说的话写进文件，比每轮口头重复可靠。DSH 会读这些文件（`CLAUDE.md` 也认）：

| 放哪 | 管多大范围 |
|---|---|
| `~/.dsh/AGENTS.md`（Windows：`%USERPROFILE%\.dsh\AGENTS.md`） | 你所有的会话 |
| 项目根目录 `AGENTS.md` | 这个项目 |
| 项目根目录 `AGENTS.local.md` | 只给你自己的覆盖，不进版本库 |
| 子目录里的 `AGENTS.md` | 只管那个子目录 |

写法：一条规则一到三行，写死的东西（构建命令、目录约定、不许动的文件、输出格式）。不要写密钥和内部网址。

要知道它只是"建议"：DSH 把它当作参考信息给模型，模型多数时候照做，但不是强制。真要拦住的事（不许删、不许联网）靠权限和审批，不靠 AGENTS.md。

## 把重复的做法写成技能（Skill）

一类任务有固定做法，就写成技能。和插件的区别：技能是一份 Markdown 说明，agent 读了照着做；插件是代码，给 DSH 加能力。

放哪（同名时靠前的优先）：

1. `<项目>/.dsh/skills/<名字>/SKILL.md`
2. `<项目>/.agents/skills/<名字>/SKILL.md`
3. `~/.dsh/skills/<名字>/SKILL.md`
4. `~/.agents/skills/<名字>/SKILL.md`（Claude Code 等工具也读这里，可以共用一套）

改了不用重启，DSH 会自动发现。

格式：

```markdown
---
name: cr-draft
description: 起草 3GPP CR（修改建议）。用户要写 CR、改规范条款、出带修订的 Word 时用。
---

# 起草 CR

1. 先确认规范号、版本、要改的条款，没给就问。
2. 从 3GPP FTP 下载对应版本的规范，只读要改的条款和它引用的条款。
3. ……
4. 交付：带修订的 .docx，加一段改动说明。列出改了哪些条款。

条款编号规则见 references/numbering.md，只在新增条款时读。
```

要点：

- `description` 最要紧：agent 先只看到名字和描述，靠它决定用不用。写清"做什么"和"什么时候用"。
- 正文写步骤和交付标准。很长的细节放 `references/` 下，正文里说什么情况下去读，按需加载，不占上下文。
- 手动调用：在输入框打 `/cr-draft 你的要求`。
- 测一个技能：一次明显该用的、一次相近但不该用的、一次手动调用，三种都对才算好。
- 技能库可以放 git 仓库，克隆到 `~/.agents/skills`，几台电脑共用。

## 写 prompt：给 agent 一份"任务契约"

模糊的话换来模糊的结果。一个好任务说清五件事：

```text
目标：把 TS 38.331 第 5.3.5 节里 RRC 重配置的流程整理成一页说明。
范围：只读 specs/ 目录和 3GPP FTP，不改任何文件。
交付：notes/rrc-reconfig.md，每个结论标出处（规范号、条款号）。
证据：最后列出读过的文件和条款。
停止点：要联网下载新文件、或要动 specs/ 以外的文件时，先问我。
```

几条习惯：

- "做完"要有证据：改了的文件、跑过的测试、产出的文件、引用的条款。让它同时交结果和证据。
- 大活先 `/plan`：agent 先探索、出计划，你批准了再动手。
- 跨很多轮的活用目标（`/goal` 或让它建 goal）：重启、恢复会话后还记得要做完什么。
- 思考档位按需选：查个东西、改个小地方用"关"或"低"，难题、长任务用"高"或"最高"。Ferry 的默认是"高"。

## 子 agent、工作流、团队

- 一两个子任务：用子 agent。`spawn` 从零开始（干净的上下文），`fork` 带上当前对话（做复查、续写）。
- 很多个同类子任务一起跑（比如同时读十份文稿各出一段摘要）：用工作流（workflow）。适合只读的、有边界的扇出；不要拿它做要改文件的活。
- 多个 agent 长期分工：Agent Teams，共享一个任务板。
- 多个 agent 并行时按文件或目录划清边界，别让两个同时改一个文件。并发别开太高，容易撞上 DeepSeek 的限流（服务端会自动重试两次，再多就报错了）。
- 子 agent 交回的"已开始"不等于"已完成"，看它交的结果和证据。

## 插件

- 第一个装插件市场类插件（`dsh-plugin` 或 `dsh-market`），之后在网页里一键装。
- 推荐清单和工作电脑上不建议装的，见 [PLUGINS.md](PLUGINS.md)。
- 装之前看源码、锁版本。插件和 DSH 同等权限运行；从 GitHub 装、带构建脚本的，pnpm 会要你在 `allowBuilds` 里放行，等于允许它在你电脑上执行代码。
- DSH 还在预览期，插件经常只认某几个 DSH 版本，升级 DSH 前先看插件支不支持。

## 好玩、好用的做法

- 飞书里指挥 agent：[dsh-lark-bot](https://github.com/PlutoKeating/dsh-lark-bot)、[dsh-feishu-bridge](https://github.com/ailoushu666/dsh-feishu-bridge)。走飞书长连接，不用公网地址；手机上发消息派任务、批准操作、收进度。它们通过 DSH 自己的接口调用 DSH，模型调用照样走 Ferry。
- 定时任务：让 agent 每天早上把 3GPP 某个工作组新上传的文稿列出来、挑相关的写摘要（DSH 自带的定时任务，或 dsh-automation 插件）。电脑得开着。
- 看上下文：dsh-context 能看到上下文由什么组成、占了多少、什么时候被压缩，长任务变"笨"时先看它。
- 会话记录复盘：模型看到的一切（系统提示、思考、工具结果、子 agent）都在会话记录里，可以搜索、从某一步分叉重来。
- 批量和脚本：`dsh --profile headless "任务"` 跑一次就退出，可以写进脚本；还有 Python SDK 能把 DSH 嵌进自己的程序。
- 离线语音输入：官方的语音插件在本地识别（约 1 GB），不上传声音。
- 手机远程控制电脑上的 DSH（DeepSeek Phone Harness、dsh-pocket）：家里电脑可以，工作电脑上多半不合规。

## 装了 dsh-llm-ferry 要注意的

- 上面这些都兼容：不管哪个插件、哪个子 agent 调模型，最后都经 Ferry 出去。
- 子 agent 有 Codex、Claude Code 两种"外部程序"提供方，它们是独立程序，直接连自己的模型接口，Ferry 拦不到。DSH 默认没开，工作电脑上也别开。
- 看图类插件把图片发到自己的云端，也拦不到，工作电脑上别装。Ferry 的模型本来就能看图。

## 针对 3GPP 工作的建议

1. 写一个项目级 `AGENTS.md`：规范放哪、文件命名规则、引用格式（规范号 + 版本 + 条款号）、"不确定的条款号先查，不许编"。
2. 写几个技能：
   - 找规范、下载指定版本（3GPP FTP 的目录规则写进去）；
   - 读会议文稿、按模板出摘要；
   - 对比同一规范两个版本的某个条款；
   - 起草 CR。
3. 带修订的 Word：DSH 自带的 Word 技能（office-docx）明确说不做修订，只会普通改写。ferry 已经有带修订的 Word 能力，下一步值得把它移植成 DSH 的技能加命令行工具，CR 才能在 DSH 里直接出。
4. 批量处理文稿用 PTC 预设或工作流，省来回、省钱。
